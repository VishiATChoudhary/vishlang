# VishLang v0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn Vishi's raw writing exports into a local QLoRA adapter on Qwen3-4B and serve `rewrite(text)` over MCP so Claude Code can rephrase drafts in his voice.

**Architecture:** A Python CLI (`vishlang`) with a linear pipeline: parse exports into paragraphs, clean and filter them with a heuristic AI detector, synthesise (neutral, original) pairs with the base model, fine-tune with `mlx_lm.lora`, serve the adapter behind a FastMCP stdio server. Everything runs on the Mac; no network except the one-time Hugging Face model download.

**Tech Stack:** Python 3.12, `uv`, `mlx-lm` (train + inference), `mcp` (FastMCP), stdlib for everything else (`mailbox`, `email`, `csv`, `json`, `tomllib`, `re`). `pytest` as dev dependency.

**Spec:** `docs/superpowers/specs/2026-10-30-vishlang-design.md` (relative to `vishlang/`). Read it first.

## Global Constraints

- Project root is `vishlang/` inside the shennies `VishLang` worktree. All paths below are relative to it. It is its own git repo (Task 1 runs `git init`), later added to shennies as a submodule.
- Runtime deps: `mlx-lm`, `mcp`. Nothing else. No PyTorch, no transformers, no langdetect.
- Base model id: `mlx-community/Qwen3-4B-Instruct-2507-4bit`. Adapter is never fused.
- LoRA start values: rank 16, lr 1e-4, 1000 iters, batch 2, 16 layers, max_seq_length 1024.
- Cleaning defaults: min 8 words, AI score threshold 0.5, WhatsApp merge window 2 minutes, holdout 10%.
- Pair target: 3k to 10k. Blind test: 20 items, pass = rewrite picked at least 15 times AND mean AI score drops.
- `data/` and `adapters/` are gitignored. Nothing of Vishi's text is committed. Fixtures under `tests/fixtures/` are synthetic.
- Author identity comes only from `vishlang.toml` (`[author] names`, `emails`). Text by anyone else is never written to disk.
- No em dashes anywhere: code, comments, docs, commit messages, prompts.
- Commits: conventional prefix, end body with `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.
- Tests needing the real model are marked `@pytest.mark.slow` and skipped unless `VISHLANG_SLOW=1`.

## Review Focus

Inputs the spec implies but a naive build breaks on. Each has a pinned test in the owning task.

1. **Exports with BOM or CRLF line endings** (Windows WhatsApp, Takeout CSV). Expected: parsed identically to clean UTF-8. Test in Task 3.
2. **mbox message with only a `text/html` part.** Expected: tags stripped, text kept, not silently dropped. Test in Task 4.
3. **Rewrite called with no prose** (empty string, or only a subject line and bullets). Expected: input returned unchanged, LM never called. Test in Task 9.
4. **LM output with preamble or think block** (`Here is the rewritten text:`, `<think>...</think>`, wrapping quotes). Expected: stripped; if nothing remains, original block returned. Test in Task 9.
5. **Pair generation interrupted overnight.** Expected: rerun skips paragraphs already neutralised, no duplicates in `train.jsonl`. Test in Task 7.

- [ ] **Step 4: Implement `ai_score`**

Four sub-scores, each clamped to `[0,1]`, averaged with weights `0.4, 0.2, 0.2, 0.2`:
- `lexicon`: (focal hits * 3 + review-word hits) per 100 words, scaled so 2 per 100 = 1.0. Focal set and review-word filter copied from the reference `check.py` (open-class style words minus its STOP set).
- `emdash`: em dashes per 100 words, 1.0 at 1.5.
- `triads`: count of `X, Y, and Z` patterns (regex `\w+, \w+,? and \w+`) per sentence, 1.0 at 0.5.
- `flatness`: `1 - min(1, stdev(sentence_lengths) / mean(sentence_lengths))`; 0 if fewer than 3 sentences.

Load the CSV once at import via `importlib.resources`.

**Interfaces:**

- Produces:
  - `split_blocks(text: str) -> list[tuple[str, bool]]` blocks in order with `is_prose` flag. Blocks are separated by blank lines.
